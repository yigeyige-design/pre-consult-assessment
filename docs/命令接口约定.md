# 命令接口约定

> 本文件是命令行与计分结果的**接口契约**。改 CLI 或改 `ScoreResult` 字段前，先改本文件，再改代码。
> 所有命令均在仓库根目录执行（PowerShell），统一使用 `python -m app.cli ...`。

## 1. 命令总览

| 命令 | 作用 | 退出码 |
| --- | --- | --- |
| `python -m app.cli self-check` | 冒烟：打印版本、已实现量表、可用命令 | 0 |
| `python -m app.cli list-scales` | 列出已实现量表（编码/名称/条目数/分值区间/分级） | 0 |
| `python -m app.cli rule-check` | 扫描硬性规则 R1～R9 | 0 通过；1 有违规 |
| `python -m app.cli score --scale <编码> (--answers <文件> \| --demo)` | 计分并输出 JSON 结果 | 0 成功；1 输入或业务错误 |
| `python -m app.cli report --scale <编码> (--answers <文件> \| --demo)` | 计分并输出中文报告片段 | 0 成功；1 输入或业务错误 |
| `python -m app.cli health [--json]` | 健康检查：版本、量表、规则扫描结论；`--json` 输出机器可读结果 | 0 健康；1 存在规则违规 |
| `python -m app.cli verify` | 规则扫描 + 全部单元测试，一键验收 | 0 通过；1 未通过 |

> R9（接口三同步）约束：本表必须覆盖 `app/cli.py` 中 `COMMANDS` 的全部子命令，
> 新增、改名、删除命令时，本表与 `README.md` 命令表必须同步更新，否则 `rule-check` 报红。

`score` / `report` 的 `--scale` 缺省为 `adl`；既不给 `--answers` 也不给 `--demo` 时，
对已内置演示数据的量表按 `--demo` 处理（当前为 `adl`、`braden`），其余量表必须显式给 `--answers`。

退出码含义：

- `0`：命令成功完成。
- `1`：业务或输入错误（`ScoreError` / `InputError`），错误信息为中文，指向具体条目或参数。
- `2`：命令用法错误（未知命令、缺少必需参数），由 `argparse` 产生。

## 2. 答案文件格式

`--answers` 接受 UTF-8 JSON 文件：

```json
{
  "scale_code": "adl",
  "answers": [
    {"item_code": "adl_eat", "option_code": "full"},
    {"item_code": "adl_bath", "option_code": "full"}
  ]
}
```

规则：

1. `scale_code` 必须与 `--scale` 一致，不一致按输入错误处理。
2. 每个 `item_code` 在本次提交中只能出现一次，重复即报错。
3. 必填条目缺失时整体报错，并在 message 中列出缺失条目编码；不得以 0 分补齐。
4. 未知 `item_code` / `option_code` 一律报错，不做静默忽略。

## 3. `score` 输出格式

标准输出为一段 UTF-8 JSON（便于被其他程序消费）：

```json
{
  "scale_code": "adl",
  "scale_name": "日常生活活动能力评定量表（Barthel 指数）",
  "standard_ref": "WS/T 888—2026 附录B 表B.1",
  "total": 85,
  "max_total": 100,
  "item_scores": {"adl_eat": 10, "adl_bath": 5},
  "item_labels": {"adl_eat": "独立进食", "adl_bath": "独立完成"},
  "level_label": "轻度依赖",
  "advice": "存在轻度依赖……",
  "missing": []
}
```

> 上例为节选：`item_scores` / `item_labels` 实际包含该量表的全部条目，`total` 为全部条目得分之和。

字段含义：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total` | int | 总分（各项得分之和） |
| `max_total` | int | 该量表满分 |
| `item_scores` | object | 条目编码 → 得分 |
| `item_labels` | object | 条目编码 → 所选选项的中文标签 |
| `level_label` | string | 分级名称，来自 `app/scales.py` 的 `levels` |
| `advice` | string | 分级对应的中文建议 |
| `missing` | array | 缺失条目编码；成功时为空数组 |

## 4. `report` 输出格式

标准输出为中文纯文本，固定包含四段：

1. 标题与元信息（量表名、标准来源、评估时间、对象）。
2. 总分与分级（含结论说明）。
3. 分项得分（条目序号、名称、得分 / 该条目满分、选项标签）。
4. 合规说明（固定尾注：不作诊断依据，请医师确认）与生成工具版本行。

> 分项得分行的 `得分 / 条目满分` 便于核对条目权重；条目满分由 `scales.py` 中该条目的最大选项分值推导，
> 不在报告层硬编码。生成工具版本行取自 `app.__version__`，用于报告追溯。

## 5. `verify` 输出格式

```
[规则扫描] R1 计分返回类型 ......... 通过
...
[单元测试] 运行 N 项，失败 0 项
验收结果：通过
```

`N` 为当前用例总数，随 `tests/` 增减而变化，不属于接口契约；判定只看 `失败 0 项` 与末行 `验收结果：通过`。
失败时最后一行必须是 `验收结果：失败`，并以退出码 1 结束。

## 6. `health` 输出格式

默认输出中文纯文本，固定六行、顺序固定（`--json` 模式只输出 JSON，不输出下列任何一行）：

```
【系统健康检查】
版本：0.1.0
已实现量表：2 张（adl、braden）
规则扫描：9/9 通过
检查时间：2026-11-04 10:30:00
结论：健康
```

说明：

- "已实现量表"一行由 `SCALE_REGISTRY` 实时推导，量表数量随实现进度增长（当前 2 张）。
- "规则扫描"一行的分母为规则总数，当前 9 条（R1～R9）；`rule_passed < rule_total` 时结论为"存在规则违规，请先修复"。

`--json` 输出等价结构（字段与 `app/health.py` 的 `to_payload()` 一致）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | string | 系统版本号 |
| `scale_count` | int | 已实现量表数量 |
| `scale_codes` | array | 量表编码列表 |
| `rule_total` | int | 规则总数（当前为 9） |
| `rule_passed` | int | 通过的规则数 |
| `ok` | bool | 规则是否全部通过 |
| `checked_at` | string | 检查时间（本地时区 `YYYY-MM-DD HH:MM:SS`） |

健康检查不依赖网络与任何外部数据，也不写任何文件；但规则扫描需要**只读**遍历 `app/` 下的源码文件，
因此进程内会有文件读取，探活时需保证源码目录可读。
`ok=false` 时退出码为 1，`ok=true` 时为 0。
